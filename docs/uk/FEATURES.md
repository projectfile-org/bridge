# Можливості

## Можливості проєкту

### Громадські документи без копіювання

- Настанова для дописувачів, кодекс поведінки, політика безпеки та сторінка підтримки створюються з однієї декларації, тож ніколи не суперечать одне одному.
- Політика використання ШІ в одному файлі каже, яка допомога вітається, а що поза межами, замість розкиданих нотаток репозиторієм.
- Заява про різноманіття та інклюзивність починається з громадського шаблону й несе твої власні нотатки про зусилля.
- Кожен файл вище генерується мовами, які ти обираєш, — іспанська та українська включені, а будь-яка інша мова йде тим самим шляхом, коли ти додаєш її формулювання.
- Власність і підтримка теж покриті: `CODEOWNERS` спрямовує рев’ю, а файли фінансування показують спонсорам кожне місце, де ти приймаєш допомогу.

### Документи функцій і шляху, що включають твоїх батьків

- Ти пишеш один короткий файл на функцію, а оглядовий документ збирається сам — включно з розділом readme, що його цитує.
- Те, що публікують твої батьківські проєкти, з’являється під їхнім власним іменем, оновлене щоразу, коли ти регенеруєш.
- Перевірка змін ніколи не потребує мережі: вона перечитує зафіксований документ і показує, що відхилилося.

### Кожне дзеркало форжу розповідає ту саму історію

- Опис, домашня сторінка й теми на GitHub, GitLab і Forgejo надсилаються з projectfile — редагуєш один раз, і всі три дзеркала збігаються.
- Налаштування репозиторію живуть поруч із кодом, який вони описують, під контролем версій, а не в трьох окремих вебформах.
- Дзеркало, якого в тебе немає, просто нічого не отримує: жодних помилок і жодних порожніх заглушок.

### З ліцензією та готовий до цитування

- `LICENSE` записується з твоїм правовласником і роком на місці, тож опублікований файл — це готовий текст, а не шаблон.
- Повний текст кожного ліцензійного терміна, який ти декларуєш, постачається поруч під `LICENSES/`, по одному файлу на термін.
- `CITATION.cff` тримається в синхронізації, тож дослідники цитують проєкт правильно без зайвих зусиль з твого боку.

### Одне місце для метаданих твого пакунка

- Твій `package.json` для JavaScript чи TypeScript слідує за projectfile, а зміни там повертаються назад — версія ніколи не новіша з одного боку, ніж з іншого.
- Твій `composer.json` для PHP тримається в тій самій синхронізації, щоб Packagist бачив те, що каже projectfile.
- Твій `pyproject.toml` для Python теж синхронізується, а розділи, які редагуєш вручну, лишаються саме такими, як ти їх залишив.
- Твій `shard.yml` для Crystal теж покрито: реліз шарда починається з projectfile, а не з другої копії тих самих даних.

### Readme, що встигає за проєктом

- Інструкції зі встановлення та користування описують те, що проєкт справді постачає — образ контейнера, пакунок чи бінарник, — з одним рецептом на кожен спосіб отримання.
- Проєкти контейнерів отримують один рядок завантаження на кожен реєстр, куди публікують, тож жоден напрямок не загублено і жоден застарілий не лишився.
- Бейджі, споріднені проєкти та посилання на громадські документи збираються самі з тієї самої декларації.
- Перелік функцій з’являється й усередині readme — мовою читача, коли існує переклад.

### Починай за хвилини, лишайся в синхроні потім

- Новий проєкт починається з інтерактивного помічника, що визначає екосистему й пропонує посилання форжів і реєстри з адреси репозиторію та стеку.
- Сканери читають робочу копію — стек, авторів, віддалені адреси — назад у projectfile, тож документ починається правдивим і лишається правдивим.
- Одна команда оновлює кожен згенерований файл; названий один — оновлюється лише той файл.
- Перевірка генерує без запису й показує кожен змінений або відсутній файл як diff, завершуючи збірку помилкою, коли ти просиш.

### Кожен інструмент читає ті самі списки

- Файли винятків для Git, контейнерів, npm і ШІ-асистентів походять з одного списку включень і винятків — шлях, проігнорований в одному місці, ігнорується скрізь, де важливо.
- Конфіги лінтерів і редактора, як-от yamllint, browserslist та атрибути Git, виводяться з тієї самої декларації.
- Уразливість, яку ти приховав один раз, лишається прихованою однаково в Trivy, Grype, OSV-Scanner та audit-ci.
- Автоматизація релізів теж тримає одну форму, тож підвищення версій і нотатки кожного релізу поводяться однаково завжди.
